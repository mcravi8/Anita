# Buddy for Mac · 0.14.0

Buddy is a personal Mac app with minimal direct messages, 3D avatars, and agents whose names, roles, instructions, shapes, and colors you can change independently.

On first launch, choose your first Buddy's name and what they should help with. Change their look opens the four shapes and seven colors; More options includes their role. Start chatting saves the agent and opens their empty conversation. Setup choices survive reopening, and a failed save retains them for retry. Fresh installs start without a fixed sample team. Existing workspaces keep their agents, chats, drafts, settings, and shared files; this update opens setup alongside that saved work. Back to my chats leaves setup for later, and Settings → Your first Buddy resumes it. After completion, that setting edits the actual agent. Available service connections and shared-file access follow the requested default-on policy, with removals available per agent.

Open Buddy in Applications. Text conversations now use your existing ChatGPT sign-in through the official Codex app-server installed on this Mac. Replies stream into the chat, can be stopped, and can be retried after a failure. Each agent has its own direct-message history. Groups have a separate shared history and a real coordinator: it chooses a spokesperson, assigns up to three useful contributions, runs independent work together, passes completed work to dependent reviewers, and combines the results into one streamed reply. The main chat stays quiet; the small Teamwork link opens actual assignments, status, and contributions on request. Settings → Connections lists installed service connections available through your ChatGPT account. Every agent, including newly created agents, starts with access to every available connected service. Choose a service to remove access for individual agents. New connections become available automatically; explicit removals persist. Supported actions are enabled. Reading tools run normally; sending, deleting, publishing, and other changes request user review in the conversation through the connector’s approval flow. Updated instructions are explicitly applied before each reply. Chats, drafts, and agent settings survive app restarts.

## Connection

Choose ChatGPT or Claude in Settings → AI provider. ChatGPT and connected-service features require the Codex CLI and a ChatGPT sign-in on the same Mac. Claude conversations use a Claude Console API key stored in Keychain. Buddy discovers Codex in `/opt/homebrew/bin`, `/usr/local/bin`, or `~/.local/bin`. If needed, open Settings → AI provider → ChatGPT → Connect. Sign-in finishes in the browser; credentials remain managed by Codex. Buddy does not read, copy, display, or save the authentication token.

The ChatGPT connection accepts subscription authentication, removes API-key environment variables from its child process, selects an available default model, and uses the account's subscription limits. It never falls back to OpenAI API-key billing. The separate Claude connection uses Console API credits and its configured estimated spending limit. Connection details are available from the small caption under the composer or Settings.

This integration follows OpenAI's documented app-server path for personal/local apps. It is not a commercial or hosted deployment. See [Codex App Server](https://learn.chatgpt.com/docs/app-server) and [Authentication](https://learn.chatgpt.com/docs/auth).

## What works

- First-agent onboarding with saved drafts, optional appearance/role choices, real connection status, and a checked save before opening the new chat.
- Real direct conversations, independent agent instructions and histories, streamed answers, Stop, Retry, and interrupted-reply recovery.
- Create a new agent, or copy an existing agent's shape and configuration without changing the original.
- Real group conversations with configurable membership and goal, role-based assignments, dependent handoffs, shared history, one combined reply, and Stop/Retry. Group execution uses only connections enabled for every member; individual access removals apply to the whole group.
- Real connected-folder files: agents and you can read, create, and edit text/code up to 1 MB and DOCX/XLSX/PDF documents up to 32 MB in the shared folder and additional folders you connect. Chat cards come from successful native saves. Two agents cannot overwrite the same old version; the second rereads and merges. Previous contents are backed up, and Saved versions lets you restore them. File access defaults on and can be removed per agent. Groups require all members’ access.
- Real agent suggestions from direct and group conversations, with native pending records and human-only editable approval. Shared task boards remain frontend previews. Old sample direct messages collapse once a real conversation begins and are excluded from model history.
- Drafts survive switching chats and reopening Buddy. Multiple agents may answer separate direct messages concurrently.
- Native save/export dialogs and standard Mac menus: Command–N, Command–K, and Command–comma.

## This Mac

Requires the installed Computer Use plugin and the ChatGPT desktop app on this Mac. Buddy uses the documented app-server `mcpServerStatus/list`, `mcpServer/tool/call`, and elicitation protocols; it does not copy credentials or use private IPC. Plugin app access and macOS Screen Recording/Accessibility permissions still apply. OS prompts and sensitive credential/security/financial actions require the user to take over.

Global Mac access starts off until you select Connect this Mac. Once connected, every registered agent has Mac access by default; remove it in their Tools settings or the This Mac panel. Group workers respect the group’s shared access. One agent holds the Mac at a time; another waits or reports that it is busy. File and service work can continue independently. The Mac must remain on; this is not an always-on cloud computer.

App access is reviewed for the current reply. Buddy accepts only empty-form requests from the verified Computer Use server for the exact app currently being requested by an active, permitted run. It does not fabricate credentials, device verification, or permanent grants. Every click, key press, typing, value change, and scroll has an exact native review. Operation arguments are bounded and cannot contain executable code. Controls must exist in the observed app. If the app changes while the review is pending, no operation is sent; the agent must observe again. Snapshots are consumed before delivery. Stop, access removal, disconnect, and restart prevent replay; uncertain outcomes remain visible in the durable action history.

Your preference is ChatGPT-subscription-only cloud work. OpenAI documents dots’ included cloud computers in ChatGPT, but no supported provisioning or attachment route for Buddy was found. No separate VM, hosting account, or API billing is created. ## Agent suggestions

Ask Chief or another agent to suggest a missing teammate. `buddy_propose_agent` saves a pending record and adds a review card to the actual reply. It creates no agent, task, message in a new DM, or group membership. The main chat remains quiet, with a small pending-suggestions badge and New chat → Agent suggestions for later review. Shape and color choices expand on request. Edit name, role, instructions, tools, and group membership before choosing Save for later, Decline, or Approve & add. New agents follow the user's default-on access preference; individual file access may be removed in the review, and service access through Connections after approval.

Only the bundled interface's main-frame native bridge can decide suggestions. The model has no approval or agent-creation tool. The native backend validates the current workspace, registered source, names, lengths, appearance, group capacity, and decision revision. Approval atomically writes one agent to the actual workspace. Stable proposal/agent identity makes duplicate or uncertain retries return the committed agent. A separate receipt-write failure is recovered from that committed workspace record, including the user's edited configuration. Queued old UI saves cannot remove a newly approved agent or its approved membership. Declined suggestions cannot be approved later. At most three suggestions are saved per request and twelve may remain pending in a workspace. Invalid/corrupt proposal records fail without being discarded.

`agent-proposals.json` stores suggestions, original configuration, saved edits, source conversation/reply, and decisions locally. Pending cards remain reviewable after stopping a reply or restarting. Group member suggestions attach to the parent group reply. Internal coordinator turns have no proposal tool. No proposal automatically resumes a task or delegates work after approval. The native proposal checks, real model tool calls, isolated Mac approval journey, and phone layout evidence are recorded in `../buddy-proposals-verification.json`.

## Connected folders

The folder button opens actual files. Buddy starts with its own shared folder under `~/Library/Application Support/Buddy/Projects/<workspace>`. Folder & access → Change shared folder replaces that root; Connect another folder adds a folder on your Mac without replacing it. Up to twelve additional folders can be connected. The folder selector appears when more than one root is available. Agents discover these roots with `buddy_list_folders`, then use their stable `folderId` with list, read, and write tools. Show in Finder opens the selected root. Disconnect folder removes additional access without deleting files. Connecting, changing, or disconnecting a folder stops current file work; disconnected and outdated folder identities cannot be reused. Each root belongs to its workspace. Corrupt saved folder registrations reject additional access. File paths must remain inside their registered root. Hidden paths, symbolic links, hard links, devices, deletion, and file execution are unavailable. HTML opens in a sandboxed preview; code remains text.

Writes use a full-content SHA-256 version and atomic replacement, serialized across Buddy agents. Stale agent edits and detected edits from other apps are rejected. The model is told to reread and merge. Manual conflicts keep your draft and provide Compare latest version; you explicitly merge and save. Existing file permissions are preserved. Previous contents and save receipts are stored outside the shared folder under `ProjectHistory/<workspace>`; restoration checks the current version again and creates another recoverable edit. A saved file remains saved even if you later stop its chat. Up to 60 file calls are allowed per model turn. Folder listings show up to 200 files and eight directory levels; other supported paths can be read by name. Text and raw binary tools support 1 MB; Office/PDF files support 32 MB.

The app-server exposes native dynamic tools only to member turns that can do file work. The coordinator plans with accurate worker-access context; it has no file tools. Synthesis receives verified save receipts. The first direct reply after this upgrade starts a file-enabled session and includes the latest twelve real messages, up to 2,000 characters each; your full visible chat remains saved. Later replies resume that session normally. File contents are sent to the ChatGPT model only when a file tool reads them or your request creates/edits them.

`project-folders.json` preserves the existing primary root. `connected-folders.json` stores only additional workspace-scoped folder identities and paths. A real subscription-backed agent searched the web, created a file in an additional folder, read it, and edited it while preserving its original contents; both saves have recoverable versions. Native Mac controls were checked with isolated test data. Evidence and limitations are recorded in `../buddy-local-tools-verification.json`.

## Local data

`~/Library/Application Support/Buddy/workspace.json` stores the interface state. `conversations.json` stores only Buddy's direct-message agent-to-thread mapping. Group model turns use fresh ephemeral threads; worker session IDs and private planning responses do not enter this mapping. The workspace stores actual group messages and inspectable work products, not internal reasoning. Each group turn receives the most recent twelve real group messages (up to 1,200 characters each); sample content and private direct messages are excluded. Codex manages its own conversation logs and sign-in. On a request timeout, `last-connection-error.json` records only the operation name and timestamp, without message text or credentials. Browser-preview storage remains independent. A workspace reset uses a fresh namespace so it cannot reuse another workspace's conversation history. Updating the app keeps existing data. `connection-access.json` version 2 stores only service IDs explicitly blocked for each workspace and agent; it contains no credentials. The earlier opt-in format migrates to the requested default-on policy. Once removed, a service stays removed across app restarts and temporary disconnection. Malformed saved permissions block access rather than silently discarding removals. `conversation-policies.json` tracks the tool policy applied to each thread. When access changes, the next reply forks the existing history into a thread with the new policy. Changing access stops current direct replies and groups using that member. Editing a group stops its current reply before changing its membership or goal. Each request is bounded to one planning turn, at most three specialist turns, and one synthesis turn; each internal turn has a three-minute deadline that pauses while a real user review is waiting. Single-member groups answer directly. Failed contributions block dependent tasks; the combined reply shows partial work and offers Retry. Internal activity never appears as extra direct messages.

The bundled interface loads without a server or internet connection; generating a new reply needs internet access. Buddy starts its own local Codex process over private pipes, without opening a network listener, and closes it when Buddy quits. Analytics are disabled for this process.

## Build and verification

With Xcode or Apple's command-line tools installed, quit Buddy and run `python3 build.py --install`. Keep this directory beside `relay`. The script compiles Apple silicon and Intel binaries for macOS 13+, builds the face icon, packages the frontend, and applies/verifies a local ad-hoc signature. It updates only `/Applications/Buddy.app`. Temporary app staging lives in `.noindex` directories and is removed; packages and rollback backups are ZIP archives, never additional searchable apps. The installer leaves Application Support, browser profiles, and Keychain untouched, refuses active work, and skips replacing an identical build. Omit `--install` for an archive-only build, or use `python3 install.py --check` to verify the package without changing the installed app. Do not create alternate test/check apps. This is a personal build, not a notarized public release.

Run native transport checks with `python3 run-tests.py` (requires Python 3). They verify real orchestration routing with a test adapter (parallel workers, dependent handoffs, failed dependencies, cancellation, bounded plans, trusted registered members, and history isolation), common group connection scope, default-on access for existing/new agents and newly connected services, durable individual removals, legacy migration, corrupt-settings handling, effective service restrictions, reviewed actions, durable grants/revocation, workspace and agent isolation, short-response latency, large fragmented history responses, UTF-8 integrity, partial JSONL frames, and rejection of previous stopped-turn events during a new retry. ## Connected actions

Gmail currently exposes enabled tools for sending, forwarding, drafts, labels, archive, and deletion. Buddy now enables these supported actions alongside reading. Connection access remains on for every agent by default; durable individual removals and group intersections are preserved. Existing conversations fork when this action policy changes, retain history, and receive authoritative current instructions so earlier read-only guidance does not prevent a requested reply.

When the app-server issues `item/tool/requestUserInput`, Buddy binds it to the exact active thread, turn, workspace, registered agent, and visible reply. A compact card shows the provider’s real question and options, plus recipient, subject, and content when supplied in the matching tool arguments. Nothing is pre-approved. The bundled main-frame bridge alone can submit a choice; it checks current registration and connection access again. Stop, access removal, stale requests, app shutdown, and restarts cannot submit acceptance. Secret-input requests are rejected; credentials stay in ChatGPT. Unsupported shell, credential/device-proof forms, or unrelated permission requests remain unavailable. Computer Use has the separate bounded review path described above.

The review stays inside the DM or group reply. After submission it shows waiting for the actual result; a successful tool event produces a compact completion receipt, with provider identifiers when supplied. Declines and tool failures remain distinct from successful actions. `connected-actions.json` stores scoped previews, decisions, and real receipts locally, without RPC identities or credentials. Accepted actions whose outcome is missing become uncertain on interruption/restart. Subsequent model turns receive this evidence and must check the service before retrying, rather than blindly sending again. A malformed action journal pauses new work instead of discarding uncertainty. For revisions, decline the proposed action and tell the agent what to change. The approval never edits the underlying queued tool call.

Tests use an isolated protocol fixture that writes only local receipts addressed to `example.invalid`; it cannot send mail or access the network. The native review UI, phone layout, decision errors, group wait/resume, durable uncertainty, access revocation, and single-effect checks are recorded in `../buddy-actions-verification.json`. The real Gmail tool catalog and a real ChatGPT conversation with the new configuration were checked. No real email was sent during verification.

The 0.10 update restores the shared confirmation-toast function and presents model-capacity errors in plain language. It never automatically retries a potentially consequential action.

Buddy 0.11.0 — documents and in-app previews

Agents now create and edit native DOCX, XLSX and PDF files through scoped document tools. Word supports styled paragraphs and tables on creation, targeted paragraph edits and appends; original package media, relationships and styles remain in place. Excel supports multiple sheets on creation and targeted text/number/boolean/formula cell edits, retaining existing cell styles and other workbook parts. Formula caches are invalidated after changes and Excel recalculates on open; Buddy does not run Excel’s calculation engine. PDFKit provides searchable PDF creation, text/choice form filling, text and highlight annotations, page rotation and added text pages. Printed PDF text is preserved. Signed and protected documents reject unsupported edits.

Files opens previews directly: a Word reading view with headings and table rows/columns, an Excel grid with sheet switching, rendered PDF pages with paging, formatted Markdown, sandboxed HTML, image previews and code/text. Reading previews do not reproduce every Office layout/style feature. Full preview opens a separate Buddy window: Word uses macOS’s formatted text importer; PDF, images and common media use Quick Look. Support for specialist formats depends on macOS. The original file is never given to a preview editor; native preview uses a private temporary snapshot. Manual Edit and the chat tools use the same version checks, serialized commits, binary backups and restoration. HTML preview has no scripts, app bridge, external requests or navigation privileges. Documents are never executed by the file engine.

Any regular file format can also be read or saved as exact base64 bytes through explicitly bounded binary tools (up to 1 MB). This is byte-level access, not a promise of semantic editing of every proprietary format. Unsupported formats show metadata and can be revealed in Finder. Text/Markdown/HTML/code supports 1 MB; Office/PDF and native file storage support 32 MB. Archive expansion/entry/XML limits apply. Existing folder boundaries, link exclusions, per-agent permissions and saved versions apply to every format. Files remain local until the user asks an agent to read them. No new runtime installation, API key or paid service is required.

Verified with native regression tests, independent python-docx/openpyxl/pypdf readers, compressed Office packages, a real subscription agent creating and editing all three document formats, and isolated native UI checks of previews and a spreadsheet edit.

## Buddy 0.14 — private browser sign-in

Settings → Browser sign-in opens a separate Chrome profile for each agent. Sign in through Chrome’s profile controls to make Google Password Manager available; Gmail website sign-in alone may not enable password sync. Private handoff runs ordinary Chrome without a debugging connection or injected agent scripts. The queue pauses and Buddy’s desktop observation tools are blocked while that private window is open. Finish private sign-in closes that browser instance and resumes a paused task, which must verify the resulting website session. A persisted privacy marker keeps access blocked across a worker restart until the old profile is closed and the handoff is finished.

Workers request a small native sign-in card on the currently observed HTTPS website. Existing logins can use Chrome’s already-filled same-origin POST form without exposing the value to the model. When Chrome needs an account choice, OS unlock or sign-in confirmation, the user takes over privately. New account requests always present a decision and open private Chrome, where the user can select a Google-saved credential or generate/save a new password. Buddy has no password-vault read/export tool or custom password database. Authentication-page observations expose no form text, controls or values; known private values are scrubbed from results and error messages. Chrome profile and Keychain paths are excluded from Buddy file tools, including through a connected parent folder.

After website-specific consent, a native email-code broker supports same-origin POST forms with autocomplete=one-time-code, a full visible recipient address, and an unambiguous verify/confirm button. It checks the matching connected Gmail account, searches at most five fresh messages from the site’s host, requires Gmail DMARC authentication and the exact recipient, and rejects ambiguous, stale, recovery, payment and previously used codes. Mail bodies and codes stay in native/bridge memory, outside model requests, web state and saved journals. Only message IDs and operation receipts are saved. Unsupported forms, delegated email-sender domains, masked recipients, identity-provider challenges, CAPTCHA, account recovery and OS security prompts go to the user. Live Gmail profile/search response shapes were checked without reading a message body; real verification mail has not been tested. Synthetic mail and local inert Chrome forms cover the verification path. Google sync, saved-password availability and website behavior still require a real user sign-in; unattended login on every site is not promised.
